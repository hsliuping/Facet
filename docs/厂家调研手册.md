# 厂家调研手册

新厂家接入 Facet 网关前的调研清单。调研结论直接决定它在系统里的形态（免费层 / 按量付费 / 包月套餐）和接入工作量，请按本手册逐项核实并留痕。

配套文档：《厂家接入指南》（调研完成后的实施步骤）。

---

## 0. 调研原则

1. **一切结论以官网为准**。宣传稿、第三方博客、模型市场描述都不能作为依据；每条结论记录来源 URL + 核实日期（对照 `docs/官网验证清单.md`、`docs/厂家模式官网核实表.md` 的格式）。
2. **区分数据面与管理面**。推理用的 key（`sk-…` / `ark-…`）通常只能调模型；用量、余额、套餐往往在控制面接口，鉴权方式可能完全不同（key 直查 / 登录态 Cookie / AK+SK 签名）。这是接入复杂度的最大变量。
3. **调研产出物**：厂家模式条目草稿（`providers.json` 形状）、用量接口探测记录、待确认问题清单。三样齐了才算调研完成。

## 1. 厂家与账号面

| 调研项 | 要回答的问题 | 留痕 |
|---|---|---|
| 官网 / 控制台 | 主站、开放平台、控制台 URL 各是什么 | URL 列表 |
| 注册门槛 | 是否要实名、是否要企业认证、海外手机号是否可注册 | 结论 + 依据页 |
| Key 获取 | 在哪个页面创建 key（`keys_url`）；一个账号能建几把 key；key 是否可设权限/额度 | URL + 截图要点 |
| Key 类型 | 数据面 key、管理面 AK/SK、控制台登录态各自长什么样、各管什么 | 类型清单 |
| 密钥安全 | key 是否只在创建时明文可见、是否支持轮换 | 结论 |

## 2. 计费与套餐（决定系统里的模式归属）

系统模式键只有三种：`coding`（编程包月）、`agent`（Agent 包月）、`payg`（按量付费），见 `src/facet/gateway/providers.py` 的 `MODE_KEYS`。

| 调研项 | 要回答的问题 |
|---|---|
| 免费层 | 有没有永久免费层（`free_forever`）或按日免费（`free_daily`）？免费模型清单、限额（rpm/rpd/tpm/tpd）、是否要绑卡 |
| 注册赠金 | 新用户送多少、有效期多久、是否与免费层叠加 |
| 按量付费 | 按 token 计费的模型价格表；有没有消费上限、欠费行为（401/403/429 哪种） |
| 包月套餐 | 有没有 Coding Plan / Agent Plan / Token Plan 这类包月包？档位、价格、窗口语义（5 小时 / 周 / 月）、重置规则、超量行为（降速 / 按量计费 / 直接拒） |
| 显示位置归属 | 包月套餐 → 订阅页；按量付费 / 免费层 → 渠道卡「厂家用量」行。调研结论里明确写属于哪类 |

## 3. API 接口面（数据面）

| 调研项 | 要回答的问题 |
|---|---|
| 协议 | OpenAI 兼容 / Anthropic 兼容 / 自研？决定渠道 `protocol` 字段 |
| base_url | 数据面完整地址（含 `/v1` 与否） |
| models 端点 | `GET /models` 是否开放、返回的 id 是否可直接调用 |
| 鉴权 | `Authorization: Bearer` 还是自定义 header |
| 能力边界 | 流式、Function Calling、多模态（vision）、embedding、上下文长度 |
| 错误语义 | 429（限流 vs 配额耗尽）、401/403 的区分；配额耗尽的响应标记（对照 `server.py` 的 `QUOTA_MARKERS` / `ACCOUNT_SCOPED_MARKERS`） |
| 特殊怪癖 | 不接受的参数、非标字段（如 Ark 上 Kimi 不收 temperature，网关里有 `normalize_kimi_temperature` 处理）。凡是要在网关里做请求归一化的，逐条记录 |

## 4. 用量 / 余额接口（决定用量接入可行性）

这是《厂家接入指南》第 5 步的输入，调研时要拿到**可复现的探测记录**。

| 调研项 | 要回答的问题 |
|---|---|
| 端点 | 余额 / 用量 / 套餐窗口分别在哪个 URL（GET 还是 POST） |
| 鉴权 | API key 直查（最理想）/ 控制台登录态 Cookie / AK+SK 签名（参考火山 `ark_quota.py` 的 HMAC 流程）/ 完全没有 |
| 响应字段 | 余额、累计消费、充值额、窗口 used/percent/quota、重置时间戳的字段名和单位（秒 / 毫秒 / ISO 字符串） |
| 窗口语义 | 5 小时 / 日 / 周 / 月各是什么 level；重置是固定周期还是滚动窗口 |
| 调用限制 | 该接口自身的频控；能否被 TTL 缓存兜住（系统默认 300s 成功缓存 / 60s 失败重试） |
| 实测 | 用一把真 key 发请求，保存状态码 + 响应 JSON 样例（脱敏） |

已知可 key 直查的样例（可作对照）：
- OpenRouter：`GET https://openrouter.ai/api/v1/key`
- DeepSeek：`GET https://api.deepseek.com/user/balance`
- 智谱：`GET https://open.bigmodel.cn/api/biz/account/query-customer-account-report`
- 火山套餐：管理面 OpenAPI `GetCodingPlanUsage` / `GetAgentPlanAFPUsage`（AK/SK 签名）
- OpenCode Go：`opencode_quota.py`

**明确接不了的也要记录**（例：Claude Pro/Max、ChatGPT Codex 无公开用量 API），避免后人重复调研。

## 5. 免费层专项（若第 2 步确认有免费层）

| 调研项 | 要回答的问题 |
|---|---|
| 免费模型清单 | 哪些模型免费、上下文/能力是否阉割 |
| 限额口径 | rpm/rpd/tpm/tpd 分别多少、按账号还是按 key |
| 额度查询 | 有没有 CLI 或接口能查免费额度剩量（对应 `providers.json` 的 `free_quota_cmd`） |
| 限额预设 | 控制台有没有免费档预设值（`free_limit_presets`） |

## 6. 模型清单

- 全部可用模型 id；**family id 与版本化 id 的差异**（如 `kimi-k3-1-pro` vs `kimi-k3-1-pro-261024`：菜单用 family、调用要版本化 id，对照 `server.py` 里 Ark 模型的处理）。
- 哪些支持 vision / 长上下文（渠道卡的 wire 策略依赖 `channel_takes_images`）。
- 停用/下线公告在哪看（供日常维护任务同步 `models` 字段）。
