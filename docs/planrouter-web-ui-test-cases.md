## 一、现状评审

现有 `tests/test_web_ui_playwright.py`（41 条）是一套合格的**页面冒烟测试**，但不是**业务测试**：能发现白屏、脚本报错、选择器失效，发现不了"数据没渲染""保存没生效""权限没拦住"。

### 做对的部分

- gateway 用进程内 `ThreadingHTTPServer` 启动，不依赖外部进程，执行快
- `add_init_script` 提前注入 admin key，解决了懒加载面板 401 的问题
- 覆盖全部 15 个面板的导航路径，可作回归网底

## 二、测试架构约定（实现时一并落地）

```text
tests/web/conftest.py
  gateway_server  → 每个用例独享 TemporaryDirectory 作为 config/data 目录
  api             → HTTP 直连后端，用于校验"UI 操作是否真的落盘"
  admin_page      → 注入 admin key（沿用现有做法）
  anon_page       → 不注入 key，测认证边界
  ui(page)        → Page Object：nav(tab) / toast() / modal() / wait_api(path)
```

约定：

1. **禁止** `time.sleep` 与 `wait_for_timeout`；断言统一用 `expect()` 自动重试，或 `wait_for_response` 等待接口。
2. 写操作用例打 `@pytest.mark.mutating`，串行执行；只读用例打 `@pytest.mark.smoke`，CI 必跑。
3. 用例失败时保存 screenshot + Playwright trace 到 `build/playwright-artifacts/`。
4. 每个用例的 config/data 目录互相隔离，跑完丢弃，不触碰仓库内真实配置。

优先级定义：**P0** 核心链路必须自动化 · **P1** 重要分支 · **P2** 边界与体验。
