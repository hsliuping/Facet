## 1. 背景与问题

`Facet免费额度全景.pptx` 将各厂家的免费政策分为四类：**一次性赠送 / 每日循环·签到 / 长期免费模型 / 注册代金券**。这四类是对用户的承诺，但代码里**没有对应的统一分类模型**，全部靠隐式字段推断，散落在多个入口各自实现。

同时，「接入模式」（凭证类型、是否需签到、能否查免费额度）同样没有统一建模：
- 凭证类型靠 `credential_envs` 是否为空推断；
- 能否查免费额度靠 `server.py` 里 **3 张硬编码 dispatch 表** + 1 个字段判断；
- 签到靠 `server.py` 里**硬编码的 `ModelScopeCheckinRunner`**，只认魔搭一家。

后果：每加一个厂家或改一条免费规则，都要在多个隐式判断点同步修改，漏一处就行为分裂——这正是向导免费模型测试池混入非免费模型（`openrouter/auto` 等）、以及用户反复在同一需求上返工的根因。

本设计的目标：把「免费模式」和「接入模式」变成**显式声明、单一实现点**的分类模型，所有入口只调归一化层，消除散落推断。

## 3. 设计目标与原则

1. **显式声明优先**：分类信息写在 `providers.json` 的 mode 字段里，不靠运行时推断；
2. **单一实现点**：所有分类判断收敛到 `mode_meta.py` 的归一化函数，入口只调它；
3. **平滑迁移**：新字段缺失时，归一化函数从旧字段推断，保证注册表不全量改写也能跑；
4. **前后端一致**：归一化后的值通过 `/api/providers` 暴露给前端，前端不再自己推断；
5. **可追溯**：每个 mode 的分类结果有明确依据（显式字段 or 推断规则），可在测试中锁定。

## 4. 统一建模：4 个分类维度

### 4.0 三层模型：不要混淆粒度

分类体系有三层，**层与层是组合关系，不是替换关系**：

| 层 | 表达什么 | 单一实现点 | 例子 |
|---|---|---|---|
| **model 级** | 单个模型 id 是否免费 | `probe.is_free_model`（后端）/ `isFreeModelId`（前端）——已收敛，**保持不动** | `google/gemma-4-26b:free` → 免费 |
| **mode 级** | 该接入模式有什么免费能力（本设计新增） | `mode_meta.py` 归一化函数 | openrouter/payg → `free_kind=daily` |
| **channel 级** | 用户把这个渠道标成什么档（选择） | `channel.tier` 字段 | 用户把 openrouter 渠道标 free 档 |

入口判断 = mode 级能力声明 × channel 级用户选择的组合。例如免费对齐入口 [_free_quota_mode](file:///d:/code/Facet/src/facet/gateway/server.py#L3236) 同时检查 `channel.tier == 'free'`（选择）与 `free_quota_cmd`（能力）。**注意：渠道编辑器目录勾选、向导测试池过滤是 model 级判断（`isFreeModelId`），不在本设计替换范围内。**

在 `providers.json` 的每个 mode 上新增 4 个**显式分类字段**（均可选，缺失时由归一化层推断）：

```jsonc
{
  "free_kind": "one_time",        // 免费模式分类
  "cred_kind": "aksk",            // 凭证类型
  "requires_checkin": false,      // 是否需要每日签到
  "quota_capability": "mgmt_api"  // 免费额度查询能力
}
```

### 4.1 free_kind（免费模式，对应 PPT 四类）

| 枚举值 | 含义 | 对应 PPT | 典型厂家 |
|---|---|---|---|
| `one_time` | 注册发 token，用完即止 | 01 一次性赠送 | volcengine/bailian/hunyuan/qianfan payg、teleai、scnet |
| `daily` | 按天重置 / 需每日签到 | 02 每日循环·签到 | modelscope、google、openrouter、llm7、commandcode |
| `forever` | 指定模型 0 元计费，不限总量 | 03 长期免费模型 | siliconflow、opencode、zai、zhipu(Flash)、hunyuan(44 模型) |
| `voucher` | 不送 token，送钱抵扣 | 04 注册代金券 | moonshot、xiaomi、anthropic、minimax |
| `none` | 无免费政策 | — | openai、xai、纯付费 agent 模式 |

**多值处理**：一个 mode 可能同时属于多类（如 #11 hunyuan payg 既有 `free_quota total` 又有 `free_models=44`，同时是 one_time + forever）。设计上 `free_kind` 取**主类**，主类选取规则**定死为 `forever > daily > one_time > voucher`**（长期免费是免费池基本盘，优先级最高；voucher 是钱不是 token，排最后）。附加免费能力仍由原有字段（`free_quota`/`free_models`）表达。归一化函数额外提供 `free_kinds_of(mode) -> list[str]` 返回全集，供免费模型页分组展示用。

### 4.2 cred_kind（凭证类型）

| 枚举值 | 含义 | 推断依据（缺失时） |
|---|---|---|
| `key` | 只需 API Key（data-plane） | `credential_envs` 为空 |
| `aksk` | 需 AK/SK 管理面凭据（用于额度对齐/余额查询） | `credential_envs` 非空 |

### 4.3 requires_checkin（是否需要每日签到）

| 枚举值 | 含义 | 推断依据（缺失时） |
|---|---|---|
| `true` | 需每日签到才能领免费额度 | provider ∈ {modelscope}（迁移期保留硬编码兜底） |
| `false` | 不需要 | 其余 |

**签到执行需配套注册表**：`requires_checkin` 只声明"要不要签"，"怎么签"需要 provider → checkin 函数的注册表（`CHECKIN_HANDLERS = {"modelscope": modelscope_quota.checkin, ...}`）。Runner 遍历声明了签到的渠道并从注册表取执行函数——否则第二个签到厂家来了仍要改 Runner 类，泛化就是空话。

### 4.4 quota_capability（免费额度查询能力）

| 枚举值 | 含义 | 推断依据（缺失时） |
|---|---|---|
| `none` | 查不到免费额度（厂家无 API） | 不在任何 fetcher 注册表、无 `free_quota_cmd` |
| `key_api` | 用 data-plane API Key 调厂家查询接口 | provider ∈ KEY_API_FETCHERS |
| `mgmt_api` | 用 AK/SK 调厂家管理面接口 | provider ∈ MGMT_WALLET_FETCHERS，或有 `free_quota_cmd` |

> ~~`header`~~ 枚举已删（v2 修订）：[quota.py](file:///d:/code/Facet/src/facet/gateway/quota.py) 的响应头限流解析（x-ratelimit-*）对**所有**渠道生效，属于 runtime 限流观测，与"账号级免费额度能否主动查询"是正交的两件事，不应混入本维度。

## 5. 归一化层：mode_meta.py（单一实现点）

新建 `src/facet/gateway/mode_meta.py`，提供以下函数。**所有入口（后端调度、前端渲染）只调这些函数，不再直接读原始字段做推断。**

### 5.0 依赖方向与注册表搬家（避免循环导入）

`quota_capability` 的推断依据是两张 fetcher 表。若表留在 `server.py`，而 `server.py` 又要 import `mode_meta`，就形成**循环导入**。因此：

- **fetcher 注册表随归一化层一起下沉**：`KEY_API_FETCHERS`（原 `CHANNEL_USAGE_FETCHERS`）、`MGMT_WALLET_FETCHERS`、`CHECKIN_HANDLERS` 定义在 `mode_meta.py`（或同层的 `vendor_registry.py`），值为 `provider_id -> 函数引用`；
- `server.py` **反向 import** mode_meta，原表删除；
- `*_quota.py` 各厂家模块不依赖 server，无环。

这样「能力声明（枚举）」与「能力实现（fetcher 函数）」同层，归一化判断不再跨模块引用。

```python
# 枚举常量
FREE_KINDS = ("one_time", "daily", "forever", "voucher", "none")
CRED_KINDS = ("key", "aksk")
QUOTA_CAPS = ("none", "key_api", "mgmt_api")

# 能力实现注册表（从 server.py 下沉至此）
KEY_API_FETCHERS: dict[str, Callable] = {...}      # 原 CHANNEL_USAGE_FETCHERS
MGMT_WALLET_FETCHERS: dict[str, tuple] = {...}     # (fetcher, ak_env, sk_env)
CHECKIN_HANDLERS: dict[str, Callable] = {...}      # provider -> checkin(api_key)

# 迁移期兜底：daily 等未显式声明时的可审计映射（不解析 note 文本）
# （v3：第二步已删除——32 个 mode 全部显式声明 free_kind）
FALLBACK_KINDS: dict[str, str] = {
    "modelscope": "daily", "openrouter": "daily",
    "google": "daily", "llm7": "daily", "commandcode": "daily",
}

def free_kind_of(mode: dict) -> str: ...
def free_kinds_of(mode: dict) -> list[str]: ...   # 全集，含主类+附加
def cred_kind_of(mode: dict) -> str: ...
def requires_checkin_of(provider_id: str, mode: dict) -> bool: ...
def quota_capability_of(provider_id: str, mode: dict) -> str: ...
def mode_meta(provider_id: str, mode: dict) -> dict:
    """一次性返回归一化后的 4 个分类，供 /api/providers 暴露给前端。"""
```

### 5.1 推断规则（新字段缺失时的兼容兜底）

> 原则：显式字段优先；缺失时从旧字段推断；`voucher` 不推断（必须显式声明，避免把"有余额查询"误标成代金券）。

| 函数 | 推断规则（按优先级） |
|---|---|
| `free_kind_of` | ① mode.free_kind 显式值 → ② `free_quota.period=total` → one_time → ③ 有 `free_models` 或 catalog 命中 `is_free_model` → forever → ④ provider ∈ FALLBACK_KINDS → daily（**显式映射表，不解析 note 文本**）→ ⑤ `free_limits` 非空 → one_time（保守兜底）→ ⑥ none |
| `free_kinds_of` | 在 `free_kind_of` 主类基础上，追加：有 `free_models` → +forever；有 `free_quota` → +one_time；provider ∈ FALLBACK_KINDS → +daily |
| `cred_kind_of` | ① mode.cred_kind 显式 → ② `credential_envs` 非空 → aksk → ③ key |
| `requires_checkin_of` | ① mode.requires_checkin 显式 → ② provider_id == "modelscope"（迁移期硬编码兜底，后续由显式字段覆盖）→ true → ③ false |
| `quota_capability_of` | ① mode.quota_capability 显式 → ② 在 MGMT_WALLET_FETCHERS 或有 free_quota_cmd（非 volcengine）→ mgmt_api → ③ 在 KEY_API_FETCHERS → key_api → ④ none |

> **不解析 `free_limits.note` 自然语言**（v2 修订）：原方案"note 命中'每日/每天/次/天'关键词"不可审计且多义（zhipu 的 note 同时含赠送与长期免费两句话）。改为代码内**显式兜底映射表 `FALLBACK_KINDS`**：一行一个厂家，可测试、可 review，第二步补显式字段后即删。

### 12.1 32-mode 显式 free_kind 定稿表

主类规则 `forever > daily > one_time > voucher`，口径 = PPT 四类分类：

|---|---|
| **none**（13） | volcengine/coding、volcengine/agent、bailian/agent、zhipu/coding、hunyuan/agent、qianfan/agent、xiaomi/agent、deepseek/payg、minimax/payg、minimax/agent、opencode/agent、openai/payg、xai/payg |

| **daily**（5） | modelscope/payg（+`requires_checkin: true`）、google/payg、llm7/payg、commandcode/agent、nvidia/payg |

### 12.2 free_quota 形态错配（重要发现）

`FreeQuota`（core.py `parse_free_quota`）是 **per-model 计数**：`free_quota_status` 按 `usage.model_usage(channel.name, wire, spec.period)` 逐模型扣减。而 PPT 每日循环的额度是**账户级**——给 32 个模型都挂 `free_quota{period:day, requests:50}` 会把账户级 50 次/天放大成 32×50 次/天，且与 `channel.rate.rpd`（正确的账户级强制机制）重复。**结论：账户级每日额度归 `free_limits`（documentation 层，喂控制台 preset/渠道 rate），`free_quota` 只用于真正 per-model 的一次性额度包。**

### 12.3 cred_kind / quota_capability 不做显式字段

原计划给每个 mode 补这两个显式枚举。执行时发现 `credential_envs` 字段与两张 fetcher 注册表（KEY_API_FETCHERS / MGMT_WALLET_FETCHERS）**本身就是显式声明**——再往 mode 上加一层显式枚举，唯一效果是「显式值优先于注册表」：当厂家新增/撤销查询 API 时，过期的显式值会静默覆盖自动推断，制造新的漂移点。故维持「凭证看 credential_envs、能力看注册表」的推断即可，`cred_kind_of` / `quota_capability_of` 仍保留显式字段入口（自定义厂家可手动声明），但内置注册表不填。

### 12.4 voucher 台账轻量版

本轮完成：moonshot/xiaomi/anthropic 显式 `free_kind=voucher`、免费页 voucher 分组 + 代金券金额文档化在 `free_limits.note`。未做（留待单独一轮，见 §8）：core.py 的 `FreeQuota` 增加 currency 字段、`vendor_quota` 快照的 `kind: token|money` 分列、前端钱/token 分列展示。

### 12.5 前端分组实现

`/api/maintenance` 的 `free_models.channels[]` 每行新增 `free_kind`（`free_kind_of(provider, mode)`，未知厂家 → none）；免费模型页筛选区新增「类别」按钮组（长期免费 / 每日循环 / 一次性赠送 / 注册代金券 / 未分类，仅显示有数据的类），行内厂家列加分类标签；与原「状态」筛选正交组合。前端不再自行推断分类（app.js `FREE_KIND_LABELS` 只做展示映射）。
