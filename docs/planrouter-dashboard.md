# PlanRouter 仪表板设计

## 目标

一个概览首页，把分散在各页的关键指标集中到一屏，打开控制台即见全局健康。指标围绕产品的三层价值组织：**稳定（转发面）/ 省钱（资源面）/ 省心（自主面）**。

## 位置

新增「仪表板」作为**默认首页**：侧边栏最顶部第一个菜单项（品牌下方、分组之前），boot 后默认激活。菜单 9 → 10 项。

```
[品牌 + 连接徽标]
[仪表板]            ← 新增，默认激活
—— 渠道与路由 ——
渠道配置 / 路由链 / 模型接入
—— 商务与厂家 ——
套餐订阅 / 厂家管理
—— 运行与维护 ——
运行状态 / 自维护 / 用量报表 / 请求日志
```

## 布局

自上而下：

1. **顶部 KPI 带**（复用现有 `.summary` / `.metric` 组件）：可用渠道 `X/Y`、冷却中、累计请求、累计 Tokens、月度成本、即将到期订阅。
2. **三组卡片**（对应产品三层价值），每组是一张 `.card`：

| 卡片 | 指标 | 来源字段 |
|---|---|---|
| 运行健康（稳定） | 渠道状态分布（可用/冷却/停用）、累计交接（failover）次数、不稳定模型数（负分） | `/api/state` channels: `cooling` `blocked` `handoffs` `scores` |
| 订阅与成本（省钱） | 生效/即将到期/已过期、月度等效成本、低额度告警数、即将到期订阅列表 | `/api/state`.subscriptions.summary |
| 自维护（省心） | 上次维护时间与触发方式、自动应用/待采纳建议/告警数、上次免费额度对齐时间、配置备份数 | `/api/state`.maintenance + `/api/maintenance`.free_align + `/api/backups` |

3. **近期用量趋势**：近 7 天请求数 / Tokens 小图（复用现有 `renderUsage` 的 `bars`/`sparkline` 逻辑）。

## 数据源（全部复用现有端点，后端零改动）

| 数据 | 端点 | 说明 |
|---|---|---|
| 渠道健康 / 评分 / 订阅摘要 / 维护摘要 | `GET /api/state` | 主数据源，一次拿全 |
| 用量趋势（近 7 天） | `GET /api/usage/7` | 复用现有 series |
| 免费额度对齐摘要 | `GET /api/maintenance` | 取 `free_align.{enabled,hours,reports}` |
| 配置备份数 | `GET /api/backups` | 取 `backups.length` |

仪表板加载时并行 fetch 上述 4 个端点；其余量都在前端从 `/api/state` 推导（渠道可用/冷却/停用计数、交接累加、负分计数、订阅状态、月度成本），**不新增任何后端逻辑**。

## 文件改动

| 文件 | 改动 |
|---|---|
| `static/index.html` | 侧边栏新增「仪表板」菜单项（置顶、默认 active）+ `#panel-dashboard` 骨架 |
| `static/style.css` | 少量仪表板专用布局（KPI 带格数、卡片内网格），尽量复用现有类 |
| `static/app.js` | 新增 `renderDashboard()`；`switchPage` 加 `dashboard` 分支；`boot` 默认进入 dashboard；`PAGE_TITLES` 加项 |
| 后端 | **零改动** |

## 测试与验证

- 现有 UI 测试保持通过；全量回归。
- 浏览器实测：仪表板默认打开，KPI 带、三组卡片、用量小图渲染正确，数字与各页一致；菜单切换到其它页后正常返回。

## 刻意不做

- 不新增后端聚合端点（前端足够）；不做异步实时推送（沿用现有 5s 轮询，仅达到仪表板时刷新）。
- 不做可拖拽自定义卡片（过度设计）；指标清单固定为产品三层价值的最小集。
