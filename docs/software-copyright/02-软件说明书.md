# Facet 模型路由网关软件 V1.0 软件说明书

## 第一章 软件概述

### 1.1 软件简介

Facet 模型路由网关软件（以下简称「本软件」或「Facet 网关」）是一款部署在本地或内网的大模型统一接入与智能路由软件。它把用户拥有的多个模型服务渠道聚合到一个入口，对外提供与 OpenAI、Anthropic 兼容的 HTTP 接口，对内在渠道路由、配额、健康度之间自动调度，使调用方（Claude Code、Cline、OpenHands、LangChain 等工具）只需要配置一个地址和一个密钥即可工作。

本软件不改变请求语义：发往 OpenAI 兼容接口的请求只会路由到 OpenAI 协议的渠道，发往 Anthropic 兼容接口的请求只会路由到 Anthropic 协议的渠道。若某个渠道只提供另一种协议，应在链路中放置本地协议桥接服务，本软件不做协议互转。

〔截图：控制台首页总览〕

### 1.2 解决的问题

- 多个模型服务商分别提供密钥、各自限流、各自计费，逐一手工切换成本高。
- 免费额度渠道有每日/每分钟限额，一旦耗尽会返回 429，业务方需要自行感知并重试。
- 单一上游故障时，业务中断；手工改配置无法快速恢复。
- 不同渠道的模型命名规则不同，工具侧需要固定一个模型名，难以在渠道间迁移。

本软件通过渠道聚合、自动故障转移、配额冷却、稳定性评分与内置别名机制，将上述问题收敛到网关内部，对调用方表现为一个稳定可用的模型服务。

### 1.3 主要特性

1. **单一入口、双协议**：`/v1/chat/completions`、`/v1/responses`、`/v1/models`、`/v1/messages`、`/v1/messages/count_tokens`。
2. **自动故障转移**：单次请求最多尝试配置数量的候选，失败自动切换下一个渠道或模型。
3. **配额与冷却感知**：解析 429/529 与 `Retry-After`、`x-ratelimit-reset` 等响应头，计算冷却窗口；日配额型限流冷却到次日 0 点（UTC）。
4. **免费额度优先**：同一路由内，免费渠道优先于付费渠道；免费额度耗尽时自动回避。
5. **稳定性评分**：每渠道、每模型独立计分，成功加分、失败扣分，并按时间衰减；坏模型自然沉底。
6. **内置别名**：`facet-auto`（自动路由）、`facet-cheap`（低成本优先）、`facet-agent`（面向工具调用的动态模型集合）。
7. **模型目录同步**：定时拉取各渠道的模型列表，作为候选池与推荐依据。
8. **健康探针**：对渠道和模型做可用性探测，验证失效的模型打「失效」标签（6 小时自动过期）。
9. **可视化管理控制台**：渠道、路由、订阅、请求日志、模型推荐、维护任务、用量统计一屏管理。
10. **纯标准库实现**：无第三方运行时依赖，Python 3.11+ 直接运行，也可用 Docker 一条命令启动。

### 1.4 软件组成

- 路由服务：负责请求解析、模型决策、候选调度、上游转发、响应回写与审计记录。
- 配置与状态：`router.json` 保存渠道/路由/监听等配置，`router.state.json` 保存评分、冷却、模型目录等运行时状态。
- 管理控制台：由路由服务内置提供，浏览器访问监听地址即可打开。
- 维护任务：模型目录刷新、渠道健康探针、死模型标记、免费额度对齐、订阅与通知提醒。
- 数据文件：请求日志 `requests.jsonl` 按行记录每次请求的路由结果与用量。

## 第二章 运行环境与安装

### 2.1 硬件环境

支持 x86_64 与 ARM64 主机。最低配置为 2 核 CPU、2 GB 内存、20 GB 可用磁盘；推荐 4 核 CPU、8 GB 内存。软件本身不加载模型权重，资源占用主要来自并发转发与日志读写。

### 2.2 软件环境

- 容器方式：Linux 主机，Docker 24 及以上、Docker Compose v2 及以上。
- 直接运行方式：Linux / Windows 10+ / macOS 13+，Python 3.11 及以上。
- 管理端浏览器：Chrome、Edge、Firefox 100 及以上版本。

### 2.3 容器方式安装

1. 获取本项目源码目录。
2. 在项目根目录执行 `docker compose up -d`。
3. 浏览器访问 `http://127.0.0.1:8787/`，使用管理密钥登录控制台。
4. 首次启动时，`data/` 目录会自动生成 `router.json`、`router.state.json` 与日志文件。

`data/` 目录为挂载卷，升级镜像不会丢失配置与统计数据；镜像中的静态资源与控制台代码随镜像一起更新，因此升级后需要重建镜像并重启容器。

〔截图：容器启动与目录结构〕

### 2.4 直接运行方式安装

1. 安装 Python 3.11 及以上版本。
2. 将 `src` 目录加入 `PYTHONPATH`。
3. 执行 `python -m planrouter --config data/router.json` 启动服务。
4. 服务默认监听 `0.0.0.0:8787`，端口可在配置文件的 `listen` 段修改。

### 2.5 首次登录与密钥

- 管理密钥默认值为 `admin`，用于登录控制台；部署后应立即在控制台中轮换。
- 网关密钥（调用方使用）在配置文件的 `listen.api_key` 中，建议写成 `env:ROUTER_API_KEY` 形式，真实值放在环境变量中。
- 所有 `env:变量名` 形式的配置项都在进程启动时解析，未设置的变量解析为空值。

## 第三章 快速开始

### 3.1 五步完成第一次调用

1. 打开控制台，进入「渠道」页，新增一个渠道：填写名称、协议（OpenAI/Anthropic）、上游地址、密钥、可用模型映射。
2. 在「路由」页确认 `default` 路由包含该渠道；若渠道标记为免费，可用 `$free` 宏让其自动加入所有免费路由。
3. 在「概览」页查看健康状态，点击「探测」验证渠道连通性。
4. 使用 curl 调用网关，模型名填 `facet-auto`。
5. 在「请求日志」页确认本次请求命中的渠道与模型，响应头中包含 `X-Routed-Via`。

### 3.2 第一次调用示例

```bash
curl http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $ROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"facet-auto","messages":[{"role":"user","content":"你好"}]}'
```

响应头中的 `X-Routed-Model-Mode` 表示决策方式（`auto`、`agent`、`exact`、`fallback`），`X-Routed-Via` 表示实际命中的「渠道/模型」。

## 第四章 基础概念

### 4.1 渠道（Channel）

渠道是一个上游模型服务端点，例如某云厂商的 OpenAI 兼容接口、某个订阅账号的桥接服务、某个免费额度服务。渠道包含：

- `name`：渠道名，全局唯一，用于路由引用与日志展示。
- `protocol`：`openai` 或 `anthropic`。
- `base_url`：上游根地址；若地址本身以版本号结尾（如 `/api/v3`），网关不会重复追加 `/v1`。
- `api_key`：支持 `env:变量名` 引用。
- `models`：渠道模型映射，左侧为调用方可见的模型名，右侧为上游真实模型名；`*` 表示任意模型直通。
- `priority`：渠道优先级，数值越小越优先。
- `rate`：限流参数，包含每分钟请求数、每日请求数、每分钟/每日 token 数。
- `timeout`：单次上游请求超时秒数。
- `tier`：`free` 或 `paid`，用于免费优先策略；也可在 `tiers` 中按模型单独设置。
- `proxy`：可选，为外网上游配置本地代理地址。

### 4.2 路由（Route）

路由是一组渠道的有序集合，调用方通过别名或路由名命中。路由绑定协议：OpenAI 路由只包含 OpenAI 渠道，Anthropic 路由只包含 Anthropic 渠道。路由名与协议一一对应，例如 `default/openai`、`cheap/openai`。

### 4.3 内置别名

- `facet-auto`：命中 `default` 路由，按「钉住 → 免费优先 → 评分」自动挑选。
- `facet-cheap`：命中 `cheap` 路由，优先低成本渠道。
- `facet-agent`：命中 `default` 路由，但候选为「动态模型集合」：从各渠道目录中筛出支持工具调用、健康可用的模型并按优先级排序，运行期动态选取。

调用方在这些别名下拿到的具体模型可能逐次不同，这是设计目标而非缺陷。

### 4.4 冷却（Cooldown）

渠道或模型因限流、超额、网络错误等原因失败后进入冷却期。冷却期内该渠道不再被选中；冷却结束时进入半开状态，允许一次探测请求，成功则恢复，失败则重新冷却。冷却时长由响应头决定，缺省按配置的分钟数，上限为 `max_cooldown_hours`。

### 4.5 稳定性评分

每渠道、每模型维护一个评分：请求成功加 1 分，失败扣 5 分，评分随时间衰减（半衰期到期后逐步回到 0）。同一候选组内按评分降序排列，因此近期失败的模型会自然沉底，恢复后逐步回升。

### 4.6 粘滞（Sticky）

同一会话（由请求头或请求体中的会话标识推断）在 `sticky_minutes` 分钟内优先使用上一次成功的渠道，以减少上下文切换带来的成本。粘滞只在同协议、同路由内生效。

### 4.7 死模型标签

维护探针验证失效的模型会被打上「失效」标签，并在后续请求与推荐中排除。标签有效期为 6 小时，过期后重新参与探测与候选。真实业务请求失败不会直接打标签，只会影响评分。

## 第五章 渠道管理

### 5.1 新增渠道

进入控制台「渠道」页，点击「新增」，按下述顺序填写：

1. 名称：仅使用字母、数字、中文与短横线，建议带厂家前缀，如 `bailian-free`。
2. 协议：按上游实际接口选择，不要在网关内混用。
3. 上游地址：填写到版本根为止，例如 `https://dashscope.aliyuncs.com/compatible-mode/v1`。
4. 密钥：可填明文，也可填 `env:BAILIAN_KEY`；推荐后者。
5. 模型映射：至少配置一个模型，或填 `*` 表示直通。
6. 免费标记：免费额度渠道勾选「免费」，以便参与免费优先与额度对齐。
7. 限流参数与超时：按上游文档填写，免费渠道建议设置每日上限。

〔截图：渠道编辑表单〕

### 5.2 渠道测试与探测

渠道列表提供「探测」动作：探测会向上游发起一次最小请求，验证密钥、地址与模型是否正确。探测结果会回写到渠道状态，并可作为模型目录同步的一部分。

### 5.3 启用与停用

停用渠道不会删除其配置与历史统计，重新启用后立即恢复参与路由。删除渠道会同时移除其评分与冷却状态，历史请求日志保留。

### 5.4 密钥安全

控制台在回显密钥时显示为掩码；保存时若提交掩码或空值，则沿用已存密钥，避免误清空。所有密钥只在进程内存与配置文件中出现，请求日志不记录密钥。

## 第六章 路由与别名配置

### 6.1 路由编辑

路由页可调整渠道顺序与清单。顺序即同优先级下的尝试顺序；若路由中出现 `$free` 宏，则在加载配置时展开为所有已启用、协议匹配、标记为免费的渠道，并按优先级与名称排序，新增免费渠道自动加入。

〔截图：路由编辑页〕

### 6.2 免费优先策略

当同一候选组里同时存在免费与付费渠道时，免费渠道排在前面。免费渠道因额度耗尽进入冷却后，请求自动落到付费渠道，额度恢复后重新优先使用免费渠道。

### 6.3 facet-agent 的使用与原理

面向 Agent 类工具（需要工具调用能力的客户端）推荐使用 `facet-agent`：

1. 调用方在工具配置里把模型名填成 `facet-agent`，不需要关心具体上游模型。
2. 网关遍历当前启用、未冷却的渠道，读取各渠道已同步的模型目录。
3. 依据内置模型能力注册表：明确支持工具调用的模型排在最前，能力未知的排在其后，明确不支持工具调用的模型直接剔除，不会「目录里有什么就试什么」。
4. 组内再按免费优先、稳定性评分、上下文长度排序；已被探针标记失效的模型跳过。
5. 上游失败自动切到下一个候选；失败模型的评分下降并自然沉底。

因此控制台「Agent 模型推荐」表中的顺序，就是 `facet-agent` 的实际尝试顺序，两者一致，便于排查。

〔截图：Agent 模型推荐卡片〕

### 6.4 别名与路由的对应关系

别名到路由的映射由配置文件中的 `branded_models` 段维护，缺省包含上述三个别名。路由不存在时，该别名回落到 `default` 路由，并在响应头 `X-Routed-Model-Reason` 中给出原因。

## 第七章 客户端接入

### 7.1 通用参数

- 基础地址：`http://<网关地址>:8787/v1`
- 密钥：`listen.api_key` 对应的真实值
- 模型：`facet-auto`、`facet-cheap`、`facet-agent` 或具体模型名

### 7.2 OpenAI 兼容客户端

任何支持自定义 `base_url` 的 OpenAI SDK 均可直接使用，只需把 `base_url` 指向网关并传入网关密钥。

### 7.3 Anthropic 兼容客户端

`/v1/messages` 接口接受 Anthropic 消息格式，供 Claude Code 等客户端使用；`/v1/messages/count_tokens` 为本地估算接口，不访问上游。

### 7.4 常见工具配置

- Claude Code：设置 `ANTHROPIC_BASE_URL` 指向网关，模型填 `facet-agent`。
- Cline / Roo Code：供应商选 OpenAI Compatible，Base URL 指向网关，模型填 `facet-agent`。
- OpenHands：`LLM_MODEL=facet-agent`，并配置网关地址与密钥。
- LangChain / LangGraph：`ChatOpenAI(model="facet-agent", base_url=..., api_key=...)`，需要工具调用时用 `bind_tools`。

〔截图：工具中的网关配置示例〕

### 7.5 流式响应

请求体 `stream=true` 时，网关按上游事件流原样转发，并在流结束时统计用量。客户端断开时，网关会终止上游连接，避免无效计费。

## 第八章 管理控制台

### 8.1 总览

总览页展示渠道健康状态、今日请求量、成功/失败比例、Token 用量与最近请求。顶部可切换显示免费额度使用情况。

〔截图：控制台总览〕

### 8.2 渠道与路由

见第五章、第六章。页面支持搜索、批量启停与拖拽排序。

### 8.3 请求日志

请求日志页按行展示每次请求的时间（浏览器本地时区）、渠道、模型、状态码、耗时、尝试次数与路由原因。支持按时间范围、渠道、状态筛选，并可导出 CSV。

### 8.4 模型推荐

模型推荐按当前渠道目录与内置能力表生成候选列表，标注是否支持工具调用、能力是否已知、上下文长度与评分，并在顶部给出推荐别名 `facet-agent` 及一键复制。

### 8.5 维护任务

维护页展示定时任务状态：模型目录刷新、渠道健康探针、失效模型标记、免费额度对齐、用量汇总与通知提醒。可手动触发单次执行，也可调整执行周期或关闭。

### 8.6 用量与订阅

用量页按天统计请求数与 Token 数；订阅页用于登记付费订阅的渠道归属、价格与到期日，便于成本核算。

## 第九章 自维护与健康检查

### 9.1 模型目录同步

按 `catalog_refresh_hours` 周期拉取每个渠道的模型列表，写入运行时状态，作为候选池与推荐依据。拉取失败不会影响已有目录，只会跳过本次更新。

### 9.2 渠道健康探针

按 `maintenance_hours` 周期对渠道发起探测。探测失败会写冷却与评分；探测成功会清除半开状态。探针与业务请求互不阻塞。

### 9.3 失效模型标记

探针连续判定不可用的模型被标记为失效，有效期 6 小时。标记期间该模型不进入候选与推荐；到期后自动解除并重新验证。

### 9.4 免费额度对齐

对齐任务核对免费渠道的实际模型清单与配置映射，输出差异建议并可自动改写映射，避免配置里残留已下线的免费模型。

### 9.5 通知提醒

订阅到期、免费额度即将耗尽、渠道长期不可用等事件可生成提醒，在控制台内展示。

## 第十章 运维与备份

### 10.1 数据文件

- `data/router.json`：配置（渠道、路由、别名、监听、默认策略）。
- `data/router.state.json`：运行时状态（评分、冷却、模型目录、用量计数）。
- `data/requests.jsonl`：请求审计日志，按行追加。
- `data/usage.json`：按天用量统计。

### 10.2 备份与恢复

备份 `data/` 目录即可完整保存配置与统计。恢复时停止服务、替换目录、重新启动。配置文件中的 `env:` 引用需保证对应环境变量在新环境中存在。

### 10.3 升级

容器方式升级：拉取新镜像后重建容器并启动，`data/` 卷保持不变。源码方式升级：停止进程、更新代码、重新启动。升级前建议备份 `data/`。

### 10.4 日志与排障

- 请求日志中的「路由原因」字段可解释为何选择该渠道，例如渠道粘滞、免费优先、仅剩可用渠道等。
- 响应头 `X-Routed-Model-Mode`、`X-Routed-Via`、`X-Routed-Requested-Model`、`X-Routed-Model-Reason` 可用于不回看日志就定位路由结果。
- 常见状态：401 表示密钥不匹配；429 表示该路由所有候选均在冷却；502 表示上游连接失败。

## 第十一章 常见问题

### 11.1 配置了渠道但请求仍失败

依次检查：请求协议与渠道协议是否一致；渠道是否处于冷却期；模型映射是否覆盖了请求中的模型名；上游地址是否需要代理；密钥是否正确解析（`env:` 变量是否已设置）。

### 11.2 免费渠道总是被跳过

免费渠道触发限流会进入冷却，日配额型限流会冷却到次日 0 点。控制台的渠道状态会显示冷却剩余时间；如需恢复，可等待冷却结束或手动清除冷却。

### 11.3 facet-agent 选到的模型不支持工具

说明该模型的注册表能力未知。可在控制台模型推荐中确认「工具调用」列；注册表明确标注不支持的模型不会进入候选。若出现误判，可通过维护任务重新探测并更新能力数据。

### 11.4 请求耗时很长

多为某个上游连接超时。网关会在超时后切换候选，并把该渠道置入短暂冷却；可通过调小渠道超时或调整渠道顺序改善。

### 11.5 控制台无法显示使用手册

控制台手册从运行环境读取 `docs/api-key-guide.md`。容器镜像已内置该文件；以源码方式运行且缺少 `docs/` 目录时，界面会提示手册不可用，并可跳转厂家官方文档。

## 第十二章 附录

### 12.1 请求头

- `Authorization: Bearer <网关密钥>`
- 可选会话标识：`X-Session-Id`，用于粘滞渠道。

### 12.2 响应头

- `X-Routed-Model-Mode`：决策方式（`exact`、`auto`、`agent`、`fallback`）。
- `X-Routed-Requested-Model`：调用方请求的模型名。
- `X-Route`：命中的路由名。
- `X-Routed-Via`：实际命中的「渠道/模型」。
- `X-Routed-Model-Reason`：决策原因。

### 12.3 主要配置项

- `listen`：监听地址、端口、网关密钥、管理密钥。
- `defaults`：冷却分钟数、最大转移次数、粘滞分钟数、最大冷却小时数、超时、目录刷新周期、维护周期。
- `channels`：渠道列表。
- `routes`：路由列表。
- `branded_models`：别名到路由的映射。
