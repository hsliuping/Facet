# 厂家接入指南

调研完成后（见《厂家调研手册》），按本指南把新厂家接进 Facet 网关。步骤按依赖顺序排列；某一步不适用（例如该厂家没有免费层）直接跳过并注明。

系统约束：纯 Python 标准库，无第三方依赖；前端无构建、纯静态文件。

---

## 1. 注册厂家（providers.json）

厂家注册表 `src/facet/gateway/providers.json`，格式 `{"providers": [...]}`。每厂家一个条目：

```json
{
  "id": "moonshot",
  "name": "Kimi",
  "modes": {
    "payg": {
      "label": "按量付费",
      "protocol": "openai",
      "base_url": "https://api.moonshot.cn/v1",
      "docs_url": "https://platform.moonshot.cn/docs",
      "keys_url": "https://platform.moonshot.cn/console/api-keys",
      "models_url": "https://api.moonshot.cn/v1/models",
      "tier": "paid",
      "models": []
    }
  }
}
```

要点：

- `modes` 只能用 `coding` / `agent` / `payg` 三个键（`providers.py` 的 `MODE_KEYS`）。只写该厂家真实提供的模式。
- `protocol`：`openai` 或 `anthropic`（`core.PROTOCOLS`）。
- `tier`：`paid` / 免费相关档位；免费层参数另配 `free_quota`、`free_limits`、`free_limit_presets`、`free_quota_cmd`（CLI 查额度命令）、`credential_envs`、`credential_help`（AK/SK 获取步骤）。
- `models_url` 有值的模式会被日常维护任务自动同步 `models` 字段；`docs_url` / `keys_url` 为空时从内置注册表继承（`INHERIT_IF_EMPTY`），维护任务改写条目不会抹掉它们。
- 用户可在 `<config_dir>/providers.json` 写同 id 覆盖条目（overlay），整条目替换、按上述规则继承。
- 控制台「厂家管理」页通过 `GET/POST/DELETE /api/providers` 读写；`POST /api/providers/maintain` 触发模型清单维护。

## 2. 渠道配置

渠道即一条可用的上游账号（`data/router.json` 的 `channels` 数组），控制台「渠道配置」页维护。关键字段：`name`、`provider`（**必须等于 providers.json 的厂家 id**，用量注册表靠它分发）、`protocol`、`base_url`、`api_key`、`models`、`enabled`、`account`、`business_line`、`tier`。

- 管理面凭证链：`accounts.resolve_creds(channel, config)` 按优先级取凭证 dict —— channel.creds 显式覆盖 > account.credentials（渠道 `account` 指向账号）> config.credentials[provider]（厂家级共享槽）。用量适配器、火山 AK/SK 都走它；creds dict 里的键名（如 `api_key` / `ak` / `sk`）由适配器约定。
- 数据面 key 独立放在 channel.api_key，支持明文或 `env:环境变量名` 引用（`resolve_secret` 解析）；不配管理面凭证时适配器直接回退用它。
- 免费层渠道 `tier` 填免费档；包月套餐渠道关联订阅行（`data/subscriptions.json` 的 `channels` 字段存渠道 id）。

## 3. 模型接入与协议适配

- 渠道 `models` 映射：`{"对外模型名": "上游模型名"}`。family id 与版本化 id 不一致时在映射里落定。
- OpenAI / Anthropic 兼容协议走 `convert.py` 的转换层，一般零代码。
- 厂家怪癖在 `server.py` 做请求归一化（现有样例：`normalize_kimi_temperature`）。对照《调研手册》第 3 节的「特殊怪癖」逐条落。
- vision：模型支持图片时确认 `body_has_vision` / `channel_takes_images` 的 wire 策略正确。

## 4. 免费层接入（可选）

- 免费档登记进 `src/facet/_find.py` 的 `FREE_TIERS`（与 `facts.py` 的 `FREE_TIERS` 保持同步），facts 目录会把它纳入免费候选。
- 有额度 CLI 的配置 `free_quota_cmd`，免费额度对齐命令（freealign）会用到。
- 免费额度的解析在 `core.parse_free_quota` / `quota.py`，`rpm/rpd/tpm/tpd` 限额进 `free_limits`。

## 5. 用量接入（核心步骤）

系统已有统一管道：**适配器产出快照 → `_cached_vendor` TTL 缓存 → `vendorquota.json` 持久化 → 前端渲染**。适配器是唯一要新写的部分。

### 5.1 适配器文件

新建 `src/facet/gateway/<vendor>_quota.py`，导出一个 fetcher：

```python
def fetch_xxx(api_key: str, timeout: float = 30.0, _urlopen=None) -> dict:
    """失败必须 raise RuntimeError（消息 ≤160 字，前端直接展示）。"""
```

返回快照形状：

```python
{
  "plan": "显示名",            # 套餐/账户名
  "provider": "moonshot",      # 厂家 id
  "windows": [                 # 用量窗口；没有就 []，用 summary
    {"level": "daily",         # session/weekly/monthly/five_hour/daily/budget
     "text": "免费模型今日 18 / 1000 次",  # 预格式化行（有它就照实渲染，优先）
     "percent": 1.8,           # 或百分比：剩 = 100 - percent
     "used": 1, "quota": 50,   # 或绝对值：已用 / 总量
     "reset_ts": 1731500000,   # 重置时间（epoch 秒，可 None）
     "status": "ok"},          # ok / exhausted / ...
  "summary": "",               # 无窗口时的单行余额描述（如 DeepSeek 余额）
}
```

渲染语义（`app.js` 的 `vendorUsageHtml`）：`w.text` 预格式化行优先；否则 absolute（`quota/used`）其次；否则 `percent` 窗口显示「剩 xx%」；windows 为空时显示 `summary`；都没有显示「厂家无用量窗口」。新窗口档位在 `vendorUsageHtml` 的 `levels` 映射补一行。

参考实现：`openrouter_quota.py`（text 预格式化 + budget 档）、`deepseek_quota.py` / `zhipu_quota.py`（summary 余额）、`ark_quota.py`（absolute + 签名鉴权）。

### 5.2 注册分发

`server.py` 的注册表加一行（键 = 渠道 `provider`）：

```python
CHANNEL_USAGE_FETCHERS = {
    ...
    "moonshot": moonshot_quota.fetch_xxx,
}
```

`channel_usage()` 自动完成：`resolve_creds` 取 key → 缓存键 `usage:{provider}:{sha1(key)[:12]}` → `_cached_vendor` 包 TTL（成功 300s / 失败 60s，失败保留旧快照标 `stale`，持久化 `vendorquota.json`）→ `channels_usage_payload()` 汇总。

管理面钱包（账户余额要 AK/SK 而不是数据面 key）不进上表，注册到 `MGMT_WALLET_FETCHERS`（`provider -> (fetcher(ak, sk), ak 环境变量, sk 环境变量)`，如百炼 BSS、腾讯云计费）：`channel_usage()` 先查此表，用 `resolve_creds` 取 AK/SK 对，缓存键前缀 `wallet:`；任一侧凭据缺失即不展示。

### 5.3 包月套餐走订阅管道（不同！）

包月套餐（coding / agent plan）不进注册表，走 `plan_for` / `_plan_creds_for`（`server.py`）：

- OpenCode 形态：渠道 key 直查（`opencode_quota.py`）。
- 智谱 Coding Plan 形态：复用渠道 `sk-` key（`zhipu_quota.fetch_coding_plan`）。
- 百炼 Token Plan 形态：本机 `bl` CLI 控制台会话，无需 key（`bailian_quota.fetch_token_plan`，前置 `npm i -g bailian-cli` + `bl auth login --console`）。
- 火山 / 混元形态：AK/SK 签名管理面 API（`ark_quota.py` / `hunyuan_quota.py`），AK/SK 走绑定渠道的凭证链（`resolve_creds`，见第 2 步）；providers.json 该模式的 `credential_envs` 声明 AK/SK 的环境变量名（如 `VOLC_ACCESS_KEY` / `VOLC_SECRET_KEY`、`TENCENT_SECRET_ID` / `TENCENT_SECRET_KEY`），供厂家管理页录入引导。
- 快照挂到 `subscriptions_payload()` 的行上（`vendor_plan`），订阅页与仪表板「订阅用量」卡共用 `planQuotaCell` 渲染。
- 厂家上报的 `reset_ts` 会联动 429 冷却（`_plan_reset_cooldown`，上限 `PLAN_RESET_CAP_HOURS`）。

**归属判断**：包月窗口 → 订阅管道；按量余额/按 key 预算 → `CHANNEL_USAGE_FETCHERS`（渠道卡「厂家用量」行）。

## 6. API 端点（现有端点够用则跳过）

`/api/channels/usage` 已覆盖渠道用量，`/api/subscriptions` 已覆盖订阅计划，通常零新端点。确需新端点时：

1. `server.py` 加 payload 方法（返回可 JSON 序列化的 dict）；
2. `ui.py` 的 `handle()` 里加路由（管理面鉴权自动生效）：

```python
    if path == "/api/xxx" and method == "GET":
        _json(h, 200, app.xxx_payload())
        return True
```

## 7. 前端渲染

- 渠道卡「厂家用量」行：`channelCard`（`app.js`）已按 `state.channelUsage[c.name]` 自动渲染，适配器正确则零改动。
- 厂家/厂商标签映射补条目：`app.js` 的厂商正则映射（约 `/moonshot|kimi/i`）与厂家管理页标签表。
- 静态文件改动后**递增缓存戳**：`index.html` 的 `app.js?v=…`。

## 8. 文档同步

- `docs/api-key-guide.md`：补该厂家的「获取 Key / 使用文档」指引（控制台会渲染它）。**有包月套餐的厂家必须在该节末尾加「套餐使用说明」子段**，用表格列清：档位、用量窗口（5小时/日/周/月）、余量口径（百分比 / 绝对值）、重置时间、可用模型清单、用量查询方式与接口。已接入的标注 Facet 里的展示位置（订阅页 / 渠道卡），未接入的标注「待接入 + 需调研项」。
- `docs/厂家模式对照表.md`、`docs/厂家模式官网核实表.md`：补调研结论。
- 用量接不了的写明原因（避免重复调研）。

## 9. 测试与部署验证

1. 语法门禁：`python -m py_compile src/facet/gateway/<改动>.py`；动过前端加 `node --check src/facet/gateway/static/app.js`。
2. 单元快测：适配器带 `_urlopen` 注入口，用假响应测正常/异常两条路（失败必须 raise RuntimeError）。
3. 部署到容器（`facet-router-1`）：

```
docker cp src/facet/gateway/xxx.py facet-router-1:/usr/local/lib/python3.12/site-packages/facet/gateway/
docker cp src/facet/gateway/static/app.js facet-router-1:/usr/local/lib/python3.12/site-packages/facet/gateway/static/
docker restart facet-router-1      # Python 改动必须重启；纯静态文件不用
```

4. 接口验证：`GET /api/channels/usage`（admin key 取 `data/router.json` 的 `listen.admin_key`，请求头 `X-Admin-Key`）返回新厂家快照；订阅型验证 `GET /api/subscriptions`。
5. 控制台人工验证：渠道卡「厂家用量」行显示正确；key 手填后真 key 端到端测一次；配额耗尽场景验证 429 冷却联动（订阅型）。
6. 无 key 场景：不配 key 时渠道卡无该行、接口无报错（`channel_usage` 返回 None 即静默跳过）。

## 常见坑

| 坑 | 说明 |
|---|---|
| `provider` 字段不一致 | 渠道的 `provider` 必须与 `CHANNEL_USAGE_FETCHERS` 键、providers.json 的 `id` 三者一致，否则用量静默缺失 |
| 忘记重启容器 | `server.py` / `*_quota.py` 是 Python 改动，`docker cp` 后必须 `docker restart` |
| 缓存戳没递增 | `index.html` 里 `app.js?v=` 不变则浏览器用旧前端 |
| 管理面 / 数据面 key 混用 | 推理 key 查不了用量、管理 key 调不了模型；适配器注释里写清用哪种 |
| 登录态接口 | 需要控制台 Cookie 的用量接口不接（不稳定），书面记录即可 |
| 快照字段单位 | `reset_ts` 一律 epoch **秒**（毫秒/ISO 自行换算）；`percent` 是 0–100 |
| 错误处理 | 适配器任何失败都 `raise RuntimeError(短消息)`，不要返回半截 dict；缓存层会兜住并标 stale |
| 文档路径 | `docs/api-key-guide.md` 在容器里对应 `/opt/facet/gateway/docs/`（`ui.py` 的 `GUIDE_CANDIDATES`），两个位置都要能解析到 |
