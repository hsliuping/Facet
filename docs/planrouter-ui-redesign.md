# PlanRouter 控制台重设计：左侧菜单 + 自维护中心

## 背景

两个问题：

1. **自维护内容没有体现**。后端已有完整的自维护机制（每日维护、免费额度对齐、稳定性评分、配置备份），但界面上有一半完全没有入口：

| 自维护能力 | 后端 | 界面现状 |
|---|---|---|
| 维护报告（自动修复/建议/LLM 分析） | `GET /api/maintenance` | 有（混在运行状态页） |
| 维护历史日志 | `GET /api/maintenance/logs` | 有（「维护日志」tab） |
| 免费额度对齐（FreeAlignRunner） | `POST /api/freealign/run`，写 freealign.jsonl | **无入口**：无状态、无手动触发、无历史 |
| 稳定性评分（+1/扣分/半衰期衰减） | `POST /api/score/reset`（支持全局/渠道/wire 粒度） | **仅模型徽标上的小重置钮**，无明细、无全局重置 |
| 配置备份（维护自动修复前生成 *.bak） | 无端点 | **无入口** |
| 全局手动刷新模型目录 | 无端点 | **无入口**（仅渠道行级拉取） |

2. **布局不顺手**。现在是顶部横向 7 个 tab + 居中单列，tab 多了以后横向拥挤，且页面内容与 tab 的从属关系不直观。改为传统的**左侧菜单栏 + 右侧内容区**。

## 一、布局重构

### 结构

```
┌──────────────┬──────────────────────────────────────────┐
│  侧边栏 220px │  页头（页面标题 + 保存状态 + 立即保存/导出） │
│  ─ 品牌      │ ┌──────────────────────────────────────┐ │
│  ─ 分组标题  │ │                                      │ │
│    渠道与路由 │ │           内容区（当前页面）           │ │
│    商务与厂家 │ │                                      │ │
│    运行与维护 │ └──────────────────────────────────────┘ │
│  ─ 底部：密钥 │                                          │
└──────────────┴──────────────────────────────────────────┘
```

- **侧边栏**：品牌 + 菜单分组 + 底部固定区（网关密钥 / 管理密钥 / 导出配置）。当前菜单项高亮。
- **页头**：页面标题（随菜单切换）+ 保存状态（草稿/已保存）+ 「立即保存」「导出配置」。原来的 topbar 精简合并进来；连接徽标移到侧边栏品牌下方。
- **指标条（summary）**：只保留在「运行状态」页，不再全局显示（全局显示的是渠道健康摘要，与当前页面无关反而干扰）。
- **响应式**：< 900px 时侧边栏折叠为顶部横向滚动菜单（保持移动端可用，不做汉堡菜单，避免复杂度）。

### 菜单结构（7 tab → 3 组 9 项）

| 分组 | 菜单项 | 对应现有 tab / 内容 |
|---|---|---|
| 渠道与路由 | 渠道配置 | 渠道配置 tab（平移） |
| | 路由链 | 路由链 tab（平移） |
| | 模型接入 | 模型接入 tab（平移） |
| 商务与厂家 | 套餐订阅 | 套餐订阅 tab（平移） |
| | 厂家管理 | 厂家 tab（平移） |
| 运行与维护 | 运行状态 | 运行状态 tab（去掉其中维护报告与用量部分，见下） |
| | 自维护 | **新页**（见第二节） |
| | 用量报表 | 从状态页拆出：renderUsage + renderReport（月度报表） |
| | 请求日志 | 从状态页拆出：renderRequests |

- `switchTab` 懒加载分发逻辑平移为 `switchPage`，各页数据按需 fetch，行为不变。
- 5 秒轮询（仅运行状态页）逻辑不变，跟随当前页判断。

## 二、自维护中心（新页）

一页集中展示全部自维护能力，从上到下：

### 1. 维护概览卡

- 上次维护时间 / 下次维护倒计时（来自 `/api/maintenance` payload）
- 维护周期（maintenance_hours）与免费额度对齐周期（free_align_hours）展示
- 两个手动按钮：「立即维护」（POST /api/maintenance/run，已有）、「立即对齐免费额度」（POST /api/freealign/run，已有，UI 首次暴露）

### 2. 维护报告

现状平移：最近一次报告的 applied / suggestions（一键采纳）/ alerts / llm_notes，历史可在维护历史中查看。

### 3. 免费额度对齐（新）

- 对齐开关与周期的展示（只读，周期在 defaults 里改）
- **对齐历史**：后端新增 `GET /api/freealign/logs`（读 freealign.jsonl，最近 N 条），前端列表展示每次对齐的时间、动作、结果
- freealign.jsonl 当前无读取端点，这是唯一需要新增的读取逻辑

### 4. 稳定性评分（新）

- 说明文案：服务成功 +1、不稳定扣分、半衰期衰减
- 展示当前有评分的渠道×模型列表（来自 `/api/state` 的 scores）及分数
- **重置入口补齐**（后端 `/api/score/reset` 已支持，UI 未暴露）：
  - 按渠道×模型重置（列表行级按钮）
  - 全局重置（页面级按钮，带确认弹窗）
- 模型徽标上已有的小重置钮保留

### 5. 配置备份（新）

- 后端新增 `GET /api/backups`：列出 config 目录下 `router.json.*.bak`（文件名 + 修改时间 + 大小），只读
- 前端列表展示；**不做在线恢复/删除**（避免误操作把坏配置盖回好配置；恢复走文件系统手动操作，文档说明即可）

### 6. 维护历史

现状平移：`renderMaintLogs`（读 `/api/maintenance/logs` jsonl）整体移到本页底部。

## 三、后端配套改动（最小）

| 改动 | 位置 | 说明 |
|---|---|---|
| `GET /api/freealign/logs` | ui.py 新路由 + server.py payload | 读 freealign.jsonl 最近 50 条，复用维护日志的读取模式 |
| `GET /api/backups` | ui.py 新路由 + server.py | 列出 config 目录下 `*.json.bak` / `router.json.*.bak`，按时间倒序，含 mtime/size |
| 其余 | 不动 | 渲染函数平移，保存模型（全量 POST）、认证、CSRF 不变 |

`/api/facts` 系列端点仍无入口，本次不补（属数据调试用途，留待需要时再说）。

## 四、文件与工作量

| 文件 | 改动 |
|---|---|
| index.html | 结构重写：`.shell` → sidebar + main；tab → 菜单；新增自维护页骨架 |
| style.css | 侧边栏布局、菜单分组样式、页头、响应式断点调整（900px） |
| app.js | `switchTab` → `switchPage`（菜单路由）；新增 renderMaintenanceCenter（含 freealign 历史、评分管理、备份列表）；renderUsage/renderReport/renderRequests 从状态页拆出为独立页；页头保存状态迁移 |
| ui.py | 新增 2 个只读端点 |
| server.py | freealign 日志读取、备份列表 2 个 payload 组装函数 |

## 五、测试计划

- 单元测试：`GET /api/freealign/logs`、`GET /api/backups`（写临时文件验证读取/排序/缺失容错）
- 现有 UI 测试（test_planrouter_ui.py）全部保持通过（页面路由、静态资源、config API 不变）
- 浏览器验证：菜单切换、懒加载、自维护页各卡片渲染、窄屏折叠、保存流程不受影响
